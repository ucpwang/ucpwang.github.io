## 뉴모피즘이 망하는 이유

뉴모피즘(Neumorphism)은 2020년에 등장해서 빠르게 트렌드가 됐다가 똑같이 빠르게 비판받았다. 주된 이유는 두 가지였다.

1. **접근성 문제**: 낮은 명도 대비로 시각 장애인이 UI를 구별하기 어렵다
2. **어두운 배경에서 안 된다는 미신**: 라이트 뉴모피즘만 퍼지면서 생긴 오해

두 번째는 사실이 아니다. 다크 배경에서도 뉴모피즘은 작동한다. 다만 계산이 다르다.

## 섀도우 계산 원리

뉴모피즘의 핵심은 **하나의 광원에서 오는 이중 그림자**다.

```
광원 위치: 좌상단
→ 좌상단: 밝은 그림자 (하이라이트)
→ 우하단: 어두운 그림자 (딥 섀도우)
```

라이트 모드에서는 배경보다 밝은 색과 어두운 색을 쓴다. 다크 모드에서는?

```css
/* 배경: #0f0f0f */
box-shadow:
  -4px -4px 10px rgba(255, 255, 255, 0.03),
  /* 극소량의 흰 하이라이트 */ 4px 4px 10px rgba(0, 0, 0, 0.5); /* 짙은 검정 섀도우 */
```

흰색 투명도를 0.03~0.05 정도로 극히 낮게 유지하는 게 핵심이다. 너무 높으면 부자연스럽고, 너무 낮으면 효과가 없다.

## 5가지 변형

프로젝트에서 다섯 가지 섀도우 변형을 정의했다.

| 변형     | 용도                | CSS                   |
| -------- | ------------------- | --------------------- |
| `flat`   | 기본 카드           | 외부 이중 그림자      |
| `md`     | 강조 카드           | flat보다 거리 큰 버전 |
| `lg`     | 모달/팝업           | 가장 강한 강조        |
| `inset`  | 코드블록, 눌린 상태 | 내부 이중 그림자      |
| `convex` | 태그, 버튼          | 살짝 튀어나온 느낌    |

```css
--shadow-flat: -2px -2px 5px rgba(255, 255, 255, 0.03), 2px 2px 5px rgba(0, 0, 0, 0.5);
--shadow-inset: inset -3px -3px 6px rgba(255, 255, 255, 0.03), inset 3px 3px 6px rgba(0, 0, 0, 0.5);
--shadow-convex: -2px -2px 5px rgba(255, 255, 255, 0.05), 2px 2px 5px rgba(0, 0, 0, 0.4);
```

## 접근성 해결책

뉴모피즘의 접근성 문제는 그림자만으로 경계를 표현하지 말고 **테두리를 함께 사용**하면 해결된다.

```css
.card {
  border: 1px solid var(--color-border); /* 명확한 경계 */
  box-shadow: var(--shadow-flat); /* 깊이감 추가 */
}
```

테두리가 있으면 그림자가 보이지 않는 환경(고대비 모드, 저시력)에서도 UI를 구별할 수 있다.

## 실제로 쓸만한가

솔직히 말하면, 뉴모피즘은 **질감 레이어**로 쓸 때 가장 효과적이다. UI 전체에 적용하면 무겁고, 특정 컴포넌트(카드, 코드블록, 인풋)에만 선택적으로 쓰면 세련된 깊이감을 준다.

다크 배경 `#0f0f0f`에서 `box-shadow: var(--shadow-flat)`을 적용한 포스트 카드는 실제로 꽤 만족스럽다.
